DukanKhata: Real-time POS and Udhar Khata ledger

Live siteGitHub
Java 17Spring Boot 3MongoDBReact 18 + TypeScriptViteTailwind CSSRazorpayDockerRenderVercel

The problem

Small Indian retailers sell on credit (udhar) and track it in paper books. Bills, GST invoices, mixed payments and staff commissions all end up in different places, and balances drift.

What I built

  • Multi-tenant platform with real-time POS billing, GST A4 invoices, customer ledgers and staff commission tracking.
  • Two modes: SMALL_SHOP (30-second daily closing with profit/loss badges) and LARGE_SHOP (full POS with itemized carts).
  • GST invoice printing, WhatsApp (wa.me) receipt sharing, and a localStorage offline fallback in the React app.
  • Performance: Vite code-splitting and React.lazy() separate the landing page from the Tailwind app.

Engineering decisions

Atomic split-payment checkout

One bill splits across Cash, UPI and customer credit with 0% data drift.

Anti-IDOR data isolation

Queries are scoped by owner (findByIdAndUserId), so one merchant can never read another's data.

Verified payment webhooks

Razorpay order.paid and payment.captured are checked with HMAC SHA-256 before upgrading a subscription.

Session and token security

JWT auth, single-device session eviction, 401 auto-logout via Axios interceptors, and AES-256 token encryption (OWASP MASVS).

Fast, offline-resilient UI

Vite code-splitting and React.lazy() separate the landing page from the Tailwind app; a localStorage fallback covers poor connectivity.
